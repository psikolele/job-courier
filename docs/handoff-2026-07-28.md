## 2. Bug bloccante — i 121 redirect erano inerti

**Sintomo:** `/prezzi/` → pagina 404. `/prezzi` (senza slash) → 301 corretto.

**Causa:** le 211 URL WordPress indicizzate finiscono **tutte** con lo slash (211/211 in `docs/old-urls-snapshot.txt`); le 121 regole in `vercel.json` erano scritte **tutte** senza (0/121). Nessun match → rewrite SPA → 404. Al go-live sarebbero state soft-404 tutte le URL indicizzate: esattamente il danno che il GOLIVE-PLAN esisteva per prevenire.

**Fix:** `"trailingSlash": false` in `webapp/vercel.json` (commit `05d51c2`). Una riga, 121 regole intatte.

**Perché era invisibile:** `vite dev` non applica i redirect di `vercel.json`, e il JSON riletto sembra corretto. Si vede solo provando una URL vera su un deploy vero.

## 3. Soft-404 → 404 reale

Il rewrite catch-all `/(.*) → /index.html` faceva rispondere 200 a qualsiasi URL inesistente. Google tratta il soft-404 come duplicato scarno e **non deindicizza**.

**Fix** (commit `5f355cc`): rimosso il catch-all, 14 rewrite espliciti per le route SPA + `webapp/public/404.html` statico. Scelto il file statico invece di una serverless function perché una function catch-all avrebbe richiesto un'invocazione per ogni pageview e la perdita della cache CDN, a parità di elenco route da mantenere.

> ⚠️ **Costo di manutenzione introdotto:** aggiungere una `<Route>` in `App.jsx` non basta più — va aggiunta anche ai `rewrites` di `vercel.json`. Sintomo se ci si dimentica: la pagina funziona cliccandoci dal menu ma dà 404 da URL diretta o refresh.
